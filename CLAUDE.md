# CLAUDE.md — сервер каталога «Туман»

Этот файл Claude Code читает в начале каждой сессии.

## Что это

Курсовой проект ИТМО «Туман — Языки России» (12 октября – 30 ноября 2026, защита 30 ноября). Продукт — Android-приложение с карточками по башкирскому языку и интервальным повторением. Этот репозиторий — **сервер каталога готовых наборов и сами наборы**: приложение запрашивает список наборов и скачивает выбранный набор на устройство. Всё остальное приложение делает без интернета.

Приложение, ТЗ и общие правила команды — в репозитории `tuman-langs/tuman-langs-mobile` (`CLAUDE.md`, `docs/tz.md`, `docs/team.md`). Если он склонирован рядом, запускай Claude Code с `--add-dir ../tuman-langs-mobile`.

## Что должен уметь сервер (из ТЗ)

- Отдавать список наборов и содержимое набора в JSON (`docs/api.md`).
- В каталоге не менее 3 наборов по башкирскому, всего 100+ карточек, в том числе по аффиксам.
- Формат наборов позволяет добавлять языки без изменения кода (`content/README.md`).
- Сервер работает на время проверки и защиты. Ответы предсказуемые: правильные коды, ошибки в JSON, башкирские буквы в UTF-8 без искажений.

## Архитектура

Стек: **Kotlin + Ktor** (JVM 17), Kotlinx Serialization, наборы — файлы `content/*.json`, базы данных нет. Если backend-разработчик выберет другой стек в задаче #1 и руководитель согласует, поправь этот раздел и `docs/architecture.md`, слои останутся теми же.

**Куда класть файлы — только по `docs/architecture.md`.** Прочитай его перед планом любой задачи с кодом. Кратко:

```
server/src/main/kotlin/ru/itmo/tuman/catalog/
├── Application.kt   точка входа
├── api/             маршруты, DTO, ошибки → JSON
├── core/            сценарии (use case)
├── domain/          модели, интерфейс SetRepository
└── data/            JsonFileSetRepository — читает content/
```

Главные правила: `api` → `core` → `domain` ← `data`; `domain` не импортирует Ktor и `java.io`; DTO живут только в `api`; кривой файл в `content/` не роняет сервер.

## Как мы работаем

Путь задачи тот же, что в mobile (подробно — `CLAUDE.md` и `docs/kanban-workflow.md` в tuman-langs-mobile):

```
Issue на доске → /start-task N → ветка <тип>/N-… → коммиты «#N: что сделано» → /finish-task → PR в main → ревью → /fix-review → Squash and merge
```

| Команда | Когда |
|---|---|
| `/my-tasks` | что у меня в работе и что дальше |
| `/start-task <номер>` | начать задачу: ветка и план по архитектуре |
| `/finish-task` | сдать задачу: проверки, коммит, PR по шаблону |
| `/review-pr <номер>` | проверить чужой PR |
| `/fix-review` | исправить замечания к своему PR |
| `/explain-my-work [что]` | подготовиться к защите |

Зависимости между задачами записаны в разделе «## Зависимости» каждой задачи (🚧 блокер, 🤝 договорённость, ➡️ от тебя ждут) и связями «Blocked by» на GitHub. `/start-task` и `/my-tasks` проверяют их и сразу говорят о блокерах. Пример: набор карточек нельзя оформлять, пока формат JSON не получил «ок» от сервера и приложения.

Типы веток здесь: `feature/` и `fix/` — сервер, `content/` — наборы, `docs/` — документация.

## Проверка перед PR

**GitHub Actions в этом репозитории отключены** — автоматических проверок на GitHub нет. Поэтому `/finish-task` всегда запускает проверки локально:
- `./gradlew test` — тесты сервера и проверка всех файлов в `content/` (на Windows: `.\gradlew.bat test`);
- пока кода сервера нет — проверь, что каждый JSON в `content/` открывается без ошибок и соответствует `content/README.md`: обязательные поля, уникальные `id`, нет пустых `front`/`back`.

Не добавляй в репозиторий файлы `.github/workflows/`: Actions выключены, такие файлы не будут работать.

## Правила для Claude

1. **Объясняй, а не только пиши код.** Участники — первокурсники; по правилам ИТМО каждый должен понимать и защитить любую часть работы, включая сделанную с ИИ.
2. **Сначала план, потом код** для всего, что больше пары файлов.
3. **Держись ТЗ и MVP.** Регистрация, синхронизация, ИИ-функции, озвучка, база данных в MVP не входят.
4. **Не придумывай языковой контент.** Переводы и правила башкирского проверяет контент-лид по словарям. С наборами помогай только со структурой JSON. Не меняй `front`, `back` и `example` без прямой просьбы контент-лида и не выдавай сгенерированные переводы за проверенные.
5. **Не меняй `id` опубликованных карточек:** по ним приложение хранит историю повторений.
6. **Не храни секреты в репозитории.** Ключи хостинга и пароли — только в переменных окружения или `.env`.
7. **Соблюдай архитектуру** из `docs/architecture.md`. Предлагай простые решения: сервер должен понимать и поддерживать один первокурсник.
