Помоги участнику аккуратно сдать задачу. Каждый шаг, который что-то отправляет на GitHub, выполняй только после его «да».

1. **Где мы:** `git branch --show-current`. Если это `main` — остановись: работа должна быть в ветке задачи. Номер задачи возьми из имени ветки (`feature/12-…` → #12).
2. **Что изменилось:** `git status` и `git diff main...HEAD --stat`, плюс незакоммиченное. Коротко перескажи изменения. Если в изменениях есть файлы, не относящиеся к задаче, спроси, нужны ли они.
3. **Проверка.** Запусти команды из раздела «Проверка перед PR» в `CLAUDE.md` (тесты и сборку). Тесты падают — сначала разберитесь, PR не открываем.
4. **Секреты.** Убедись, что в изменениях нет `.env`, `local.properties`, ключей, токенов и паролей. Нашёл — остановись и скажи.
5. **Коммит.** Предложи сообщение на русском в формате `#<номер>: что сделано` (например `#12: экран редактирования карточки`). После согласия — `git add` нужных файлов и `git commit`.
6. **Отправка:** `git push` (при первой отправке — `git push -u origin <ветка>`).
7. **Текст PR** по `.github/pull_request_template.md`:
   - «Что сделано» — по сути, с `Closes #<номер>`;
   - «Как проверить» — конкретные шаги;
   - «Использование ИИ» — набросай черновик по этой сессии (для чего использовали Claude, какие были ключевые запросы), но пункты «Что проверил(а) сам(а)» и «Где решил(а) иначе» **попроси участника заполнить самому**. Не выдумывай за него.
   Покажи текст, дождись правок и согласия.
8. **Открой PR:** `gh pr create --base main --title "<как в коммите>" --body-file <временный файл>`; ревьюера (руководителя) добавь, если его логин указан в `CLAUDE.md`. Если `gh` недоступен — дай ссылку на создание PR из вывода `git push` и текст для вставки.
9. **Напомни** перенести карточку в «На ревью» и прочитать замечания ревьюера. После слияния ветку можно удалить.
